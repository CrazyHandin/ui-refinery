# 真实截图评审与媒体使用

## 评审方法

先明确本次任务、方向与验收条件。视觉问题和实际交互问题分别记录；静态截图只支持其可见范围内的结论。

### 准备可比较的证据

- 改造已有界面时，条件允许就保留修改前截图；全新界面不要求伪造基线。捕获实际运行的实现，覆盖主视图及本次相关状态。
- 比较前后版本时保持窗口、数据、主题、缩放、滚动位置和交互状态一致，等待字体与素材进入稳定状态。需要比较的布局或状态差异应另列，避免误认为设计改善。
- 记录最少的环境信息，使截图能够复现。保存不同轮次，避免覆盖唯一的修改前证据；一次小修可以只用简短记录。
- 没有截图时标注视觉验证未完成；已有但未实际查看的截图不算已评审。浏览器或截图工具失败时保留失败事实。

### 按影响排序

| 维度 | 具体检查 |
| --- | --- |
| 布局与主要任务 | 用户能否定位信息和主要操作；是否遮挡、裁切、顺序混乱或装饰抢焦点 |
| 文字与密度 | 层级、对齐、长文本和数据比较是否清楚；密度是否适合实际用途 |
| 组件与状态 | 同一类控件是否一致；当前状态与反馈是否可见且可理解 |
| 个性与整合 | 构图、字体、颜色与素材是否共同表达 brief；是否存在无用途装饰或机械重复 |

先处理影响理解、操作和阅读的问题，再处理一致性与装饰细节。同一根因造成多处问题时优先修正规则或共享组件，避免逐页堆补丁。

每轮提出最多三个值得修改的问题，每项说明：

> 截图或状态及具体位置 → 可观察表现 → 对用户或视觉的影响 → 建议改动 → 如何复查。

按同一框架重新查看截图，逐项记为改善、未改善或出现回归；主操作和相关状态需实际操作确认。通常最多两轮，已满足本次验收条件即可结束。可选评分用于表达评审者的判断，不设置必须达到的分数，不将其当成客观质量或功能验证。

## 独立评审提示

仅在工具可用且当前任务允许委派时使用新上下文。提供本轮截图、目标用户/任务、brief 与必要参考；不提供代码、实施难度、历史解释、此前评分、预期分数或版本标签。无需独立代理时按同一维度自查，明确这是自查。

> 根据截图，判断界面是否适合给定用户、主要任务和视觉方向。先概括它表达的审美。检查布局与任务可见性、文字和信息密度、组件与状态一致性，以及个性和素材整合。只提出最多三个最有影响、值得修改的问题，每项注明截图或状态、位置、可见表现、影响、可执行调整和复查方法；若没有实质问题可以直接说明。保持产品用途和给定方向，区分可观察缺陷与个人风格偏好。截图无法证明的交互、性能、键盘和辅助技术行为标注为未验证。

参考图代表完成度或方向依据，不要求复制风格。有多组可比截图时可匿名排序，但应解释具体差异，不能仅凭排名宣称普遍效果提升。

## 何时使用生成媒体

- 图像：当明确主体、场景或材质支持核心表达时，编写主体、光线、材质、构图留白、配色和背景要求。将素材放入界面后检查裁切、文字可读性与整合效果。
- 循环视频：用于确实需要的自然运动。规划循环接缝、固定镜头、背景分离与页面位置；简单背景可尝试色键，复杂边缘需要可用的背景分离工具。实际确认工具结果，不预设透明通道。
- 折射等效果：依赖页面背景时，可按目标背景色渲染再分离背景；背景变化后重新检查融合。
- 连续过渡：可用前一段末帧作为后一段起点，减少主体和镜头跳变。滚动播放检查加载、定位和双向滚动，不把预渲染运动描述为实时物理模拟。
- 只有任务需要媒体时才生成。检查体积、加载、播放支持、减少动态效果和静态回退；工具或预算不足时保留可完成主任务的静态方案，并说明限制。
