# 真实数据与界面边界

用于有数据的列表、表格、表单或详情界面，以及明确的边界测试任务。普通 UI 修改只选相关正常内容和少量边界；完整压力检查按用户需求或已观察到的问题展开。

## 从数据入口构造场景

- 对关键字段确认来源、可空性、产品约束及前后端允许的长度或范围。没有找到约束时如实记录，采用可信的长值，不凭空设定上限。
- 从既有 fixture、mock、组件参数或测试数据入口注入边界内容，不先改布局来制造失败。发现问题后按任务授权修改组件或样式。
- 优先使用已有测试或开发页面；需要数据切换时放在测试环境。验证用控件不进入正式产品流程，不为普通小修专门搭建比较面板。

## 按内容选择边界

| 相关内容 | 可选样例与检查重点 |
| --- | --- |
| 人名与头像 | 很长或极短的合法姓名、中文与混排、缺失头像；检查回退、固定图标尺寸和文本空间 |
| 邮箱、链接、文件名 | 可信的长连续字符串、相近前缀和不同后缀；检查换行、完整内容入口及辨识度 |
| 说明与状态标签 | 长标题、空值、翻译后的长标签、组合 emoji；检查行高、换行、截断及字符处理 |
| 数量、金额、日期 | 按业务允许范围选 0、1、较大值、小数与不同日期长度；检查单位、精度、数值对齐和单复数 |
| 集合 | 无记录、一条、多条及实际预期上限；分别检查空状态、选择范围和已有分页或虚拟列表行为 |
| 内容或请求缺失 | 失败图片、可空字段、实际涉及的加载与请求失败；检查回退、输入保留和恢复路径 |

边界值遵守本次业务契约；无效输入只在测试校验路径时使用。邮件和链接使用 `example.com` 或 `.test` 等示例地址，避免连到真实对象。不同问题可以分散在多条记录中，同时保留单独的空列表场景。

## 看见问题后定位原因

| 表现 | 值得检查的原因与修复方向 |
| --- | --- |
| 长文本把按钮挤出容器 | 检查 flex/grid 子项的最小尺寸；为可收缩文本区域选择合适的 `min-width` 与换行策略 |
| 头像或图标被压扁 | 检查固定尺寸与收缩规则，不靠缩小全部内容补偿 |
| 重要错误或主操作文字消失 | 避免固定高度裁剪；调整布局或允许换行，保留完整操作含义 |
| 数值变化时整行跳动 | 检查可变数字宽度、单位和列对齐；必要时采用等宽数字，保留精度要求 |
| 看似同名的文件无法区分 | 按任务保留扩展名、版本或关键后缀；截断不应丢掉唯一辨识信息 |
| 数据一多就卡顿 | 复现并测量现有分页、渲染或布局瓶颈；不要仅凭记录数更换架构或安装依赖 |

在组件实际容器宽度下复查，而非只看全屏。对相关场景增加窄窗口、文字缩放，以及产品本就支持的主题或语言；不为测试擅自增加整套国际化功能。

## 证据与交付

记录触发数据、容器或窗口、状态、可见问题和修复后的同条件结果。已实际查看的运行截图、代码推断与未验证项分别说明。

用户要求检查时给出问题与建议；用户已要求修复时完成相关修复和回归，不机械套用“只报告后停下”。验证数据和结果按任务大小保留，避免把一次边界样例固化为所有产品的统一规则。
