# 移动网页的触摸与视口体验

用于移动浏览器和 PWA 的相关实现或问题排查。原生 iOS、Android 和桌面 UI 沿用各自平台能力；不要把这里的 Web 修复直接套到原生应用。

## 根据症状选择处理

| 症状或任务 | 优先处理与验证 |
| --- | --- |
| 点击后悬停效果残留 | 按 hover/pointer 能力启用悬停效果；同时保留触摸按压与键盘反馈，不根据屏幕宽度或 UA 推断设备类型 |
| 触摸反馈不清楚 | 优先保留原生按钮与明确的按压反馈；移除浏览器点击高亮前提供等价反馈，只在确有需要的区域处理 |
| 地址栏变化后高度或底部内容不对 | 根据内容选择稳定的小视口 `svh` 或动态视口 `dvh`；长内容优先检查最小高度与滚动，避免统一写死高度 |
| 刘海、圆角或底部指示条遮挡 | 在确实延伸到安全区的布局中结合 viewport 设置和 `env(safe-area-inset-*)` 留出空间；核对已有内边距，避免重复叠加 |
| 输入时页面放大或操作被键盘遮住 | 检查输入字体、页面缩放和焦点可见性；可先试清晰的约 16px 输入文字，再在目标设备验证，不以禁止缩放解决 |
| 拖拽、横向区域与页面滚动冲突 | 确认采用原生滚动还是自定义手势，再在相关区域设置 `touch-action`；不统一关闭页面手势 |

全屏布局不等于输入时仍可见。软键盘可能改变视觉视口而不改变布局视口；不能仅用 `dvh` 宣称键盘问题已解决。先验证滚动与焦点行为，确有需要再用 VisualViewport 事件辅助定位，并处理监听清理和浏览器差异。

## 保留浏览器与输入能力

- 保留用户缩放。文本、链接和输入内容维持选择能力；只在确实需要的按钮或拖拽区域限制选取，不在整个页面设置不可选择。
- 原生横向滚动优先沿用浏览器行为。自定义水平拖拽需要保留页面纵向滚动时，可以在手势表面考虑 `pan-y pinch-zoom`；处理 pointer cancel，实际检查缩放和斜向滑动。
- `touch-action: manipulation` 允许滚动与双指缩放，但会影响双击缩放；仅在适用控件考虑。避免为消除一次点击延迟全局更改手势。
- 仅在对应滚动容器需要时调整滚动链或回弹。抽屉和弹层沿用既有滚动锁，不为所有页面统一禁用下拉刷新、浏览器手势或背景滚动。
- 为金额、邮箱、验证码等相关字段选择合适的 input 类型、输入模式和回车提示；保留项目的自动填充与输入约定，避免全局禁用拼写或自动更正。
- 触摸提供即时视觉反馈；真实操作保留语义按钮的激活时机和取消路径，避免在手指刚按下时就提交。

## 分清验证环境

模拟器或桌面窄窗口可检查布局。涉及软键盘、触摸悬停、安全区和浏览器工具栏时，在可用的目标真机检查，并记录系统、浏览器以及浏览器/PWA 模式。

按变化选择相关路径：滚动时工具栏伸缩、聚焦和关闭键盘、点击与拖动取消、横竖屏或安全区、用户缩放及减少动态效果。检查主操作和错误提示是否仍可见，避免不必要地扩大测试。

没有真机时继续完成可验证部分，明确区分代码检查、模拟环境结果与待真机确认的行为。不能仅凭桌面截图声称移动端体验已验证。
