# 软件 UI 实现参考

按任务读取相关小节。以下规则用于做设计决策；不要求为每次修改创建完整文档、组件库或全部状态。

## 根据用途选择结构

| 产品任务 | 应优先支持 | 常见失配与调整 |
| --- | --- | --- |
| 产品介绍、注册或购买 | 价值理解、信任与主要行动 | 装饰抢过主要行动时，收拢视觉重心；避免把所有信息压在首屏 |
| 业务后台、数据管理 | 查找、比较、筛选与批量操作 | 重复卡片妨碍横向比较时采用表格或列表；工具靠近其作用对象 |
| 编辑器、桌面工具 | 工作区、持久上下文与高频操作 | 大面积宣传视觉挤占工作区时重分空间；沿用熟悉的菜单和快捷操作 |
| 移动任务流程 | 清晰步骤、触控操作与输入恢复 | 窄屏压缩后操作难点按时重排；保持提交位置与当前步骤易于定位 |
| 游戏菜单与 HUD | 氛围、即时反馈与游戏内可读性 | 背景或动效干扰状态识别时调整前景层级；重要状态不能只靠颜色 |

以主要任务和已有产品为准；混合产品可以采用不同区域结构，不把上表当成固定模板。

## 形成最小可复用规范

先检查现有主题、组件库和设计变量。只补足本次所需部分，避免并行建立另一套系统。

| 项目 | 需要明确的决策 |
| --- | --- |
| 文字 | 页面标题、区块标题、正文、辅助信息的角色；中文与混排回退；长内容如何显示 |
| 空间 | 控件内部、同组元素、不同区块的间距关系；内容宽度与密度是否适合使用场景 |
| 颜色 | 背景、表面、正文、弱化文字、边界、主操作与状态的语义；状态同时提供文字或图标 |
| 控件 | 常用尺寸、图标对齐、边框和圆角；适用的悬停、焦点、选中、禁用或忙碌状态 |
| 层叠与动态 | 下拉、弹层和固定区域的遮挡关系；必要过渡及减少动态效果的处理 |

将稳定的值映射到项目已有的 CSS 变量、主题配置或平台资源，而非在每个页面重复写值。不要为不同产品强制规定相同字号、间距单位或圆角。应用原生平台时沿用其组件和交互约定。

## 围绕操作补齐状态

对本次新增或改动的关键操作，先确定：用户如何触发，处理时显示什么，成功后去哪里，失败后如何继续，哪些输入或选择应保留。小任务可以口头确定；流程较多时使用简短状态表。

| 相关情况 | 应说明或实现的行为 |
| --- | --- |
| 加载或异步提交 | 反馈作用对象和进行状态，防止同一操作重复提交；避免无理由阻塞整个页面 |
| 没有数据 | 区分初次使用、筛选无结果与数据加载失败；给出适合该情况的下一步 |
| 输入无效 | 在相关字段附近说明问题，保留已输入内容，让修正与重新提交路径清楚 |
| 请求失败 | 反馈失败及可行的重试或恢复操作，避免状态看似成功或输入全部丢失 |
| 操作成功 | 让结果和位置明确；已有行更新、对话框关闭或跳转足够时，避免多重重复提示 |
| 禁用或权限限制 | 当原因不明显时提供可理解的解释；若权限由后端决定，前端状态不能替代真实校验 |

危险或不可逆操作沿用项目现有确认或撤销机制，仅在本次涉及该操作时检查。不要给所有普通按钮增加确认步骤。

## 用代表性内容检查密度

- 对实际涉及的布局选取正常内容与一个容易破坏布局的边界：长名称、较多记录、大数值、无数据或关键错误。无需为无关场景穷举。
- 表格比较保持单位、数值对齐和列含义一致；有截断时保留获取完整内容的路径。筛选结果和批量操作应清楚显示作用范围。
- 长文本决定换行或截断策略；主操作与关键错误不能因固定高度被裁掉。检查中文、英文、数字混排是否影响层级。
- 使用演示数据时使其接近真实长度和分布，并标注模拟范围；不要用空白占位推断成品效果。

## 窗口适配与键盘路径

- 根据内容开始拥挤的位置确定适配，而非只缩小字体。宽窗口检查工作区分配；窄窗口检查主要行动和当前上下文是否仍可见。
- 宽表格可以局部横向滚动、固定关键列或按任务转为摘要列表；不要为了消除全部横向滚动而隐藏必要比较信息。页面级意外溢出需排查。
- 侧栏和工具栏折叠后保留可理解的入口与当前选择；固定区域不能遮挡字段、焦点或主要操作。
- 对本次受影响的控件实际检查键盘触达、触发和焦点可见性。对话框需要验证进入、关闭及返回触发处的焦点；原生或成熟组件已有实现时优先复用。
- 检查表单标签、控件名称与状态是否有程序可识别的表达；错误、选中与成功反馈应能通过颜色以外的线索识别。用检查工具或实际操作确认的结果才记为通过。
- 文字缩放、减少动态效果与素材失败只在涉及的区域检查。未测量的对比度、屏幕阅读器行为或完整无障碍符合性保持未验证。

## 共享组件回归

改变主题变量或共享组件时，找出受影响的调用处，抽查一个已有代表性视图及相关状态。纯页面内调整无需扩展为全产品检查。分别记录视觉检查、实际操作和未验证项。
